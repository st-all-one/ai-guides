# Logs e Tratamento de Erros (PHP 7.4)

O documento comum de logs (7.2) cobre `error_log()`, `syslog()`, handlers de
erro, `trigger_error()`, níveis e `error_clear_last()`. Este complemento foca no
que o **PHP 7.3/7.4** adicionou à configuração de log via syslog e reforça
práticas relevantes no 7.4.

> Fora de escopo: quaisquer melhorias de logging de 8.x. Mantenha-se em
> `error_log`/`syslog`/`set_error_handler`/`set_exception_handler`.

## 1. Novas diretivas `syslog.*` (PHP 7.3)

Quando `error_log` está definido como `"syslog"`, ou ao usar `syslog()`
diretamente, as seguintes diretivas (7.3) controlam o comportamento:

### `syslog.ident`

`string`. String de identidade prefixada a **toda** mensagem de log.

```ini
error_log=syslog
syslog.ident=minha-app
```

```php
<?php
// Com syslog.ident=minha-app, as mensagens aparecem como "minha-app: ..."
syslog(LOG_INFO, 'Iniciando processo');
```

### `syslog.facility`

`string`. Indica que **tipo de programa** está logando (mapeia para as
instalações do syslog, ex.: `LOG_LOCAL0`–`LOG_LOCAL7`, `LOG_USER`, etc.). Só tem
efeito com `error_log=syslog`.

```ini
syslog.facility=LOG_LOCAL0
```

### `syslog.filter`

`string`. Filtra os caracteres enviados ao syslog. As opções:

| Valor | Comportamento |
|---|---|
| `all` | divide nos `\n`; todos os caracteres passam inalterados |
| `ascii` | divide nos `\n`; escape de ASCII 7-bit não imprimível |
| `no-ctrl` | divide nos `\n`; escape de qualquer caractere não imprimível |
| `raw` | envia tudo inalterado, sem dividir em `\n` (igual ao PHP < 7.3); disponível desde 7.3.8/7.4.0 |

```ini
syslog.filter=no-ctrl
```

Isso protege o syslog de caracteres de controle malformados/injetados.

> `syslog.filter` **não é suportado no Windows**.

### Exemplo completo

```ini
; php.ini (produção, Linux)
error_log=syslog
syslog.ident=minha-app
syslog.facility=LOG_LOCAL0
syslog.filter=no-ctrl
```

```php
<?php
openlog('minha-app', LOG_PID | LOG_ODELAY, LOG_LOCAL0);
syslog(LOG_INFO, "Pronto");
closelog();
```

## 2. Recapo de `error_log()` e `syslog()` (baseline)

```php
<?php
error_log('Algo aconteceu');              // tipo 0: log do PHP/Servidor
error_log('msg', 3, '/var/log/app.log'); // tipo 3: anexa a arquivo

openlog('minha-app', LOG_PID, LOG_LOCAL0);
syslog(LOG_ERR, 'Falha ao conectar');
closelog();
```

| Tipo `error_log()` | Comportamento |
|---|---|
| `0` | mecanismo de log do PHP (php.ini `error_log` ou syslog) |
| `1` | e-mail |
| `3` | anexa a arquivo |
| `4` | handler do SAPI |

## 3. `zend.exception_ignore_args` e rastros (PHP 7.4)

A diretiva `zend.exception_ignore_args` (documentada em `16-configuracao-74.md`)
remove os **argumentos** dos stack traces de exceções. Isso evita que dados
sensíveis apareçam em logs de exceção. Em produção, recomenda-se `On`:

```ini
zend.exception_ignore_args=On
```

Combine com um handler global de exceção que registre de forma controlada:

```php
<?php
set_exception_handler(function (Throwable $e): void {
    error_log('Exceção: ' . $e->getMessage());
    http_response_code(500);
});
```

## 4. Inspeção de erros (revisão)

- `error_get_last(): ?array` — último erro.
- `error_clear_last()` (7.0+) — limpa o último erro registrado.

```php
<?php
$ultimo = error_get_last();
error_clear_last();
```

## 5. Manipuladores de erro (revisão)

```php
<?php
set_error_handler(function (int $errno, string $errstr, string $errfile = '', int $errline = 0) {
    if (!(error_reporting() & $errno)) {
        return false;
    }
    error_log(sprintf('[%d] %s em %s:%d', $errno, $errstr, $errfile, $errline));
    return true;
});

register_shutdown_function(function () {
    $erro = error_get_last();
    if ($erro !== null && in_array($erro['type'], [E_ERROR, E_PARSE], true)) {
        error_log('Erro fatal: ' . $erro['message']);
    }
});
```

> Não use o parâmetro `$errcontext` em handlers (removido no 8.0).

## 6. Diretrizes

- Em produção: `display_errors=Off`, `log_errors=On`, `error_log` definido.
- Ao usar syslog, defina `syslog.ident`, `syslog.facility` e `syslog.filter`
  (7.3+) para logs limpos e seguros.
- Habilite `zend.exception_ignore_args=On` (7.4) para não expor argumentos em
  traces.
- Centralize logs com `set_exception_handler` + `register_shutdown_function`.
- Não registre dados sensíveis (senhas, tokens) em texto plano.

## 7. Resumo

- **7.3:** `syslog.facility`, `syslog.ident`, `syslog.filter` (afetam `error_log=syslog` e `syslog()`).
- `syslog.filter` aceita `all`/`ascii`/`no-ctrl`/`raw` (raw desde 7.3.8/7.4.0); não suportado no Windows.
- **7.4:** `zend.exception_ignore_args` remove argumentos dos traces.
- Baseline (`error_log`, `syslog`, handlers, `error_clear_last`) permanece.
