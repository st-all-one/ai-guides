# Logs e erros no PHP 8.5

O 8.5 melhora a observabilidade de duas formas: erros fatais finalmente
incluem stack trace, e é possível **ler** os handlers ativos de erro e
exceção. Isso permite instrumentação que preserva handlers de frameworks em
vez de sobrescrevê-los.

## Fontes

- `docs/fatal_error_backtraces.txt`.
- `docs/get_error_handler-get_exception_handler.txt`.
- `source/UPGRADING:186-196,738-746,949-952`.

### Stack traces em erros fatais

Condições anteriormente irreversíveis — como estouro de `memory_limit` ou
`max_execution_time` — agora incluem stack trace completo
(`source/UPGRADING:186-188`). Exemplo de saída:

```text
Fatal error: Allowed memory size of 2097152 bytes exhausted (tried to allocate 5242912 bytes) in ... on line 6
Stack trace:
#0 file.php(...): str_repeat('A', 5242880)
#1 file.php(...): my_heavy_function()
#2 {main}
```

Controle:

```ini
fatal_error_backtraces = On        ; default no 8.5, ZEND_INI_ALL (source/Zend/zend.c:263)
display_errors = Off               ; produção: nunca exponha ao cliente
zend.exception_ignore_args = On    ; remove argumentos dos traces (source/Zend/zend.c:1540)
zend.exception_string_param_max_len = 0 ; defesa em profundidade
```

Detalhes auditados no engine:

- O trace é capturado apenas para `E_FATAL_ERRORS` com o executor ativo
  (`EG(active)`); bootstrap/startup fora do executor não tem trace
  (`source/Zend/zend.c:1536-1542`).
- `error_get_last()` inclui a chave `trace` quando há backtrace fatal;
  `error_clear_last()` descarta o trace
  (`source/ext/standard/basic_functions.c:1440-1488`).
- O formatador injeta `"\nStack trace:\n"` na mensagem de log — parseadores
  devem tratar a mensagem como multilinha
  (`source/main/main.c:1410-1411`).
- `#[\SensitiveParameter]` é honrado também no trace fatal
  (`source/Zend/zend_builtin_functions.c:1753-1810`).
- **8.5.13 corrigiu UAFs no próprio mecanismo** (CVE-2026-129474,
  CVE-2026-129182) — quem habilita backtraces e lê `error_get_last()` em
  shutdown deve atualizar (`source/NEWS:43-47`).


- `zend.exception_string_param_max_len` limita strings no trace; não tem
  efeito com `zend.exception_ignore_args=On`
  (`source/php.ini-production:376-384`).

```php
function conectar(#[SensitiveParameter] string $senha): void { /* ... */ }
```

### Observabilidade de baixo overhead

O engine expõe *observers* (`zend_observer_error_notify`,
`zend_observer_fcall_register`) que veem erros mesmo quando um handler de
usuário intercepta — preferidos para APM/OpenTelemetry em extensão
(`source/Zend/zend.c:1544-1550`; `source/Zend/zend_observer.h:61-75`).
Em userland, use `hrtime(true)` para medições pontuais.


### `get_error_handler()` e `get_exception_handler()`

Novas funções retornam o callable ativo ou `null`
(`source/UPGRADING:738-743`; `docs/get_error_handler-get_exception_handler.txt:40-78`):

```php
function get_error_handler(): ?callable {}
function get_exception_handler(): ?callable {}
```

Uso típico: instalar instrumentação temporária e **restaurar** o handler
anterior — crucial em aplicações com frameworks que já registram handlers.

```php
<?php
declare(strict_types=1);

$erroAnterior = get_error_handler();
$excAnterior  = get_exception_handler();

set_error_handler(static function (int $no, string $str, string $file = '', int $line = 0): bool use ($erroAnterior) {
    error_log(json_encode([
        'nivel' => $no,
        'mensagem' => $str,
        'local' => "$file:$line",
        'request_id' => $_SERVER['HTTP_X_REQUEST_ID'] ?? null,
    ], JSON_THROW_ON_ERROR));
    return $erroAnterior !== null
        ? (bool) $erroAnterior($no, $str, $file, $line)
        : false; // deixa o motor tratar
});

try {
    // código instrumentado
} finally {
    restore_error_handler();
    if ($excAnterior !== null) {
        set_exception_handler($excAnterior);
    }
}
```

> Polyfill para versões antigas: `set_error_handler(null)` devolve o handler
> atual e `restore_error_handler()` desfaz a troca
> (`docs/get_error_handler-get_exception_handler.txt:93-116`). No 8.5, use as
> funções nativas — o polyfill tem janela de corrida em código concorrente.

### Depreciações que viram ruído de log

| Evento | Resultado no 8.5 | Fonte |
| --- | --- | --- |
| Output dentro de output handler | aviso de depreciação (bypassa o handler) | `source/UPGRADING:363-367` |
| Casts `(boolean)/(integer)/(double)/(binary)` | depreciação | `source/UPGRADING:368-370` |
| `case ...;` em `switch` | depreciação | `source/UPGRADING:374-376` |
| Backtick | depreciação | `source/UPGRADING:377-378` |
| `null` como offset / `array_key_exists` | depreciação | `source/UPGRADING:400-402` |
| `__sleep`/`__wakeup` | soft-deprecation | `source/UPGRADING:408-410` |
| `NAN` convertido, float fora da faixa → int | aviso | `source/UPGRADING:58-62` |
| Chave de `$_SESSION` com `|` | aviso | `source/UPGRADING:152-154` |

Configure `error_reporting=E_ALL` em desenvolvimento e trate depreciações
como dívida a corrigir — não as silencie com `@`.

### Telemetria de erros com contexto seguro

- Registre `request_id`, método, rota e duração; **nunca** registre senhas,
  tokens ou corps completos.
- `#[\SensitiveParameter]` protege argumentos em traces
  (`docs/fatal_error_backtraces.txt:60-62`).
- Para fatal errors, combine `register_shutdown_function()` +
  `error_get_last()` com os novos traces; o evento de shutdown continua sendo
  o ponto de captura.
- Use `error_log_mode=0640` e rotação; mantenha `error_log` fora do docroot.

```php
register_shutdown_function(static function (): void {
    $e = error_get_last();
    if ($e === null || !in_array($e['type'], [E_ERROR, E_PARSE, E_CORE_ERROR, E_COMPILE_ERROR], true)) {
        return;
    }
    error_log(json_encode([
        'evento' => 'fatal',
        'tipo' => $e['type'],
        'mensagem' => $e['message'],
        'local' => $e['file'] . ':' . $e['line'],
        'request_id' => $_SERVER['HTTP_X_REQUEST_ID'] ?? null,
    ], JSON_THROW_ON_ERROR));
});
```

## Verificação

- Script throwaway com `memory_limit=2M` + `str_repeat()` deve produzir
  `Stack trace:` na saída com `fatal_error_backtraces=On`.
- `php -r 'var_dump(get_error_handler(), get_exception_handler());'` deve
  imprimir `NULL NULL` sem handlers customizados.
- Com `display_errors=Off`, confirme que nenhum trace vaza para a resposta HTTP.
