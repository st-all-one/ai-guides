# 05 - Immutability and Determinism

This chapter answers which standard-library types make state immutable, how hashing and ordering behave, and how to make runs reproducible. It depends on 01 for the source pin and on 02 for the 3.15 `frozendict` gate; functional style is introduced in 04 and determinism testing in 21.

## Immutable and read-only building blocks

| Type | Guarantee | Evidence |
|---|---|---|
| `@dataclass(frozen=True, slots=True)` | Field assignment raises; no instance `__dict__` | `samples/library__dataclasses.rst:173-175`, `samples/library__dataclasses.rst:201` |
| `NamedTuple` | Tuple subclass with attribute access, indexable and iterable | `samples/library__collections.rst:864-866` |
| `MappingProxyType` | Read-only proxy, dynamic view of the source mapping | `samples/library__types.rst:387-389` |
| `tuple` / `frozenset` | Immutable; `frozenset` is hashable and usable as a key | `samples/reference__datamodel.rst:54`, `samples/reference__datamodel.rst:477-479` |
| `frozendict` (3.15) | New immutable builtin; hashable when keys and values are | `samples/whatsnew__3.15.rst:264-269` |
| `Enum` | Symbolic names bound to unique values, iterated in definition order | `samples/library__enum.rst:24-26` |

`@dataclass` exposes `frozen=False` and `slots=False` flags (`samples/library__dataclasses.rst:46`). With `slots=True` it generates `__slots__` and returns a new class (`samples/library__dataclasses.rst:201`); with `frozen=True` field assignment raises, emulating read-only instances (`samples/library__dataclasses.rst:173-175`). If `eq` and `frozen` are both true, a `__hash__` is generated by default (`samples/library__dataclasses.rst:165`); if `eq` is true and `frozen` false, `__hash__` is set to `None` (`samples/library__dataclasses.rst:167`). `_replace(**kwargs)` returns a *new* named tuple rather than mutating it (`samples/library__collections.rst:988-990`).

```python
from dataclasses import dataclass, replace
from types import MappingProxyType

@dataclass(frozen=True, slots=True)
class Config:
    host: str
    port: int

cfg = replace(Config("localhost", 80), port=443)
readonly = MappingProxyType({"retries": 3})
```

`MappingProxyType` is a read-only view, not a snapshot: when the underlying mapping changes the view reflects it (`samples/library__types.rst:389-391`). `derived` — copy the source mapping before proxying if callers need a stable snapshot. Enum values should be immutable and hashable: mutable or unhashable values carry a quadratic creation cost (`samples/library__enum.rst:287-290`).

## Hashing, equality and ordering

Hashability has a strict contract. If a class defines `__eq__` but not `__hash__`, instances cannot be used in hashable collections, and `__hash__` is implicitly set to `None` raising `TypeError` (`samples/reference__datamodel.rst:2260-2261`, `samples/reference__datamodel.rst:2276-2278`). A key's hash value must stay immutable or the object lands in the wrong hash bucket (`samples/reference__datamodel.rst:2262-2264`). By default user classes inherit `__eq__`/`__hash__` from `object`, so objects compare unequal except to themselves and `x == y` implies `hash(x) == hash(y)` (`samples/reference__datamodel.rst:2268-2271`). Ordering comparisons have reflected partners: `__lt__`/`__gt__` and `__le__`/`__ge__` are mutual reflections while `__eq__`/`__ne__` reflect themselves (`samples/reference__datamodel.rst:2219-2221`).

| Need | Mechanism | Evidence |
|---|---|---|
| Value equality + dict key | `frozen=True` dataclass or `NamedTuple` | `samples/library__dataclasses.rst:165`, `samples/library__collections.rst:864` |
| Mutable payload as key | Do not hash it; use an immutable id | `samples/reference__datamodel.rst:2262-2264` |
| Stable sort order | Implement `__lt__`, not all four comparisons | `samples/reference__datamodel.rst:2219-2221` |
| Ordered immutable mapping (3.15) | `frozendict` keeps insertion order but compares ignoring it | `samples/whatsnew__3.15.rst:270-271` |

## Reproducible order and randomness

Dictionaries preserve insertion order: keys are produced in the order added, replacing a key does not move it, and removing then re-inserting moves it to the end (`samples/reference__datamodel.rst:516-518`). This became a language guarantee in 3.7; CPython 3.6 preserved it only as an implementation detail (`samples/reference__datamodel.rst:533-535`). `frozendict` also preserves insertion order, although comparison ignores order (`samples/whatsnew__3.15.rst:270-271`).

The `random` module implements pseudo-random generators intended for modelling and simulation (`samples/library__random.rst:11`); the Mersenne Twister is deterministic and completely unsuitable for cryptography (`samples/library__random.rst:27-29`). `secrets` should be preferred over `random`'s default PRNG for passwords, tokens and related secrets (`samples/library__secrets.rst:22`). Reusing a seed value makes a sequence reproducible run to run as long as multiple threads are not running (`samples/library__random.rst:470-471`), but most algorithms and seeding functions may change across Python versions (`samples/library__random.rst:473`). `seed(a=None)` uses the current system time when `a` is omitted (`samples/library__random.rst:72-76`), so an explicit seed is required for determinism.

```python
import random

rng = random.Random(20261118)        # local generator, not global state
values = [rng.random() for _ in range(5)]
assert values == [random.Random(20261118).random() for _ in range(5)]
```

| Source of variation | Control | Evidence |
|---|---|---|
| Global PRNG seed | Instantiate `random.Random(seed)` | `samples/library__random.rst:423`, `samples/library__random.rst:470-471` |
| Wall-clock time | Inject a clock; prefer a monotonic clock | `samples/library__time.rst:301-303` |
| Clock suitability | `get_clock_info()` reports *adjustable* and *monotonic* | `samples/library__time.rst:248-252` |
| Secrets | Use `secrets`, never `random` | `samples/library__secrets.rst:22` |

`derived` — pass an `rng` and a `now()` callable into functions instead of reading module-level state; this makes outputs a pure function of explicit inputs. `derived` — record the Python version alongside a seeded artifact, because generator algorithms may change between releases (`samples/library__random.rst:473`). `derived` — prefer `time.monotonic()` for elapsed time, since a monotonic clock cannot go backwards (`samples/library__time.rst:301-303`).

## Reproducible artifacts

`derived` — a reproducible artifact is a pure function of pinned inputs: source files, locked dependency versions (see 16-18), an explicit seed and an injected clock. `derived` — sort any set-derived output before serialising, because set iteration order is not part of the immutability guarantee (`samples/reference__datamodel.rst:451`). `derived` — serialise immutable values (`frozen=True` dataclasses, `NamedTuple`, `frozendict`) so a failed build cannot leave a half-mutated intermediate. `derived` — keep global mutable registries out of transform code; module-level state is shared across imports (`samples/reference__import.rst:36-38`) and defeats the reproducibility boundary.
